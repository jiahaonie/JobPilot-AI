# 内置知识库与学习计划 MVP PRD

日期：2026-09-08

## 1. 本轮目标

让 AI Agent 开发工程师方向的求职者，在已有匹配报告的基础上，无须上传学习资料，就能得到基于产品内置资料的具体学习计划。

本轮只跑通一条核心链路：

```text
已有匹配报告
  → 用户点击生成学习计划
  → 按报告中的优先技能缺口检索内置资料
  → 生成具体任务并附参考依据
  → 保存计划，用户查看并更新进度
```

复用已有岗位、简历、匹配报告和学习计划页面。本轮主要补上“检索资料 → 生成有依据的任务”，不重新建设整套求职流程。

## 2. MVP 必须完成的功能

### 2.1 准备一份可检索的内置资料

首批来源：`D:\user\Documents\Career\AI\AI-Agents-in-Depth-zh-CN.pdf`。

由项目作者维护和审核，通过一次性导入或整理为文本的方式进入知识库。不需要资料管理后台、自动更新机制或通用 PDF 上传页面。

只验证该资料实际支持的 Agent 技能，不要求先建全量技能目录，不承诺覆盖所有 Agent 岗位要求。资料使用授权仍待确认；选定来源不代表已经入库。

### 2.2 根据匹配报告生成具体任务

沿用匹配报告的优先技能缺口，不新增优先级算法或用户信息收集步骤。系统检索相关资料，再据此组织有顺序的学习任务。

每项任务只要求包含：

- 对应技能及具体学习内容。
- 可执行的学习或实践动作。
- 明确的完成标准。
- 参考资料名称和相关原文片段。

任务不能只有“学习某技能”“完成最小实践”等通用模板。用户应能知道下一步做什么，以及如何判断完成。

### 2.3 保存并展示结果

复用现有计划详情与任务状态功能，展示任务及依据；刷新或重新打开后内容和进度仍然保留。

MVP 沿用一份匹配报告对应一份计划的规则：已有计划时直接查看，不覆盖原计划，也不提供调整、重新生成或版本切换。本轮新增能力用于尚无计划的报告，既有计划保持原样。

### 2.4 保留必要的失败处理

- 没有技能缺口：明确提示，无须生成任务。
- 部分技能缺少资料：生成有依据的部分，并列明未覆盖技能，不伪装成完整计划。
- 所有目标技能均缺少资料：提示当前资料不足，不编造任务或引用。
- 生成失败：显示失败反馈并允许重试，不保存不完整的失败结果。

## 3. 最小验收标准

使用少量真实岗位、简历和内置资料样例，完成浏览器流程与人工核对，不以建立完整评测集作为本轮前置条件。

- 无须上传用户资料，从匹配报告即可生成并打开学习计划。
- 对资料支持的技能，任务具体、与缺口相关，有可执行动作和完成标准。
- 展示的引用确实来自内置资料，能够支持任务涉及的知识内容。
- 刷新后计划仍可查看；更新任务状态后进度能够保留；已有计划不被重复生成覆盖。
- 资料不足与生成失败有明确反馈，不出现伪造内容；失败后可以重试。

实施时执行与改动相关的测试，并记录真实流程验收结果。不设置尚无依据的命中率门槛，也不增加评测页面。

## 4. 后续迭代方向

以下内容保留为后续方向，不属于本轮交付或验收范围：

- **用户补充资料**：可选上传 Agent 开发工程师相关 Markdown、TXT；增加资料处理状态与来源区分，用户资料不自动进入公共知识库。
- **学习问答**：从任务进入检索或问答，查看答案与引用。
- **计划版本管理**：用户主动调整或重新生成成功后，新版成为当前版本；旧版内容和当时进度保留且只读。目标与完成标准仍一致的任务可继承完成进度，不能仅凭同名继承；失败不影响旧版。
- **个性化排期**：收集每周可投入时间等可选信息，改善任务安排。
- **系统化离线评测**：由开发者使用数据与脚本评估主题、问题、计划支持和检索效果，区分资料缺失、检索失败与生成错误；明确 Hit@K、Recall@K 口径后再制定规模和阈值，无须用户侧评测功能。
- **知识扩充与维护**：完善技能目录、资料覆盖与更新机制，再考虑其他岗位方向或联网获取资料。

## 5. 开始实施前的必要确认

仅确认选定资料的可用性、使用授权，以及用于跑通流程的少量技能样例。完整技能目录、评测阈值和进度继承算法不阻塞本轮。

本文件描述本轮目标，不代表功能已实现。技术方案应围绕最小链路复用现有模块，不提前建设后续功能。
