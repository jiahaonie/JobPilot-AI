# 内置知识库与学习计划 PRD

状态：需求草案；岗位方向、资料来源、补充资料范围和计划版本原则已确认，技能目录与评测标准待细化。

日期：2026-09-08

## 1. 产品目标

用户只需提供目标岗位和个人简历，JobPilot AI 就应完成匹配分析，并基于产品内置知识库生成具体、可执行、有参考依据的学习计划。用户上传学习资料是可选增强，不能成为生成计划的前置条件。

本次迭代以“内置知识库支撑学习计划”为核心，资料上传和学习问答作为辅助能力，不以搭建资料管理页面作为主要交付目标。

## 2. 用户与问题

首版仅服务 AI Agent 开发工程师岗位的求职者，重点面向已有目标岗位、但不清楚如何补齐技能、缺少学习资料和学习路径的新手。

- 用户知道匹配报告中的技能缺口，但不知道从哪里开始、先学什么。
- 用户可能没有笔记、课程或参考资料，不能要求其先收集资料才能获得帮助。
- 泛化的“学习概念、完成实践”不足以指导行动，需要具体内容和完成标准。
- 已有资料的用户，希望计划能结合自己的课程或笔记，减少重复学习和寻找资源的成本。

## 3. 核心使用流程

```text
提供岗位与简历
  → 完成分析并生成匹配报告
  → 用户发起学习计划生成
  → 根据技能缺口检索产品内置知识库
  → 可选：结合用户指定的补充资料
  → 生成分阶段学习计划及参考来源
  → 用户执行任务、更新进度
  → 学习中按需查看资料或提问
```

资料上传不应打断主流程。没有用户资料时，产品仍应在自身知识覆盖范围内提供完整学习计划。

## 4. 知识库定位

### 4.1 产品内置知识库

由产品维护，作为所有用户生成计划的默认参考来源。内容需要支持以下学习决策，而不只是存放零散文档：

- 技能的核心知识点与适用场景。
- 学习该技能所需的前置知识和推荐顺序。
- 能够执行的练习或项目任务。
- 对应的产出要求与完成标准。
- 可追溯的参考资料及来源信息。

首版仅支持 AI Agent 开发工程师方向。具体技能目录需结合岗位要求和资料内容确定；不能仅凭资料数量或文件名称认定知识覆盖充分。

首批内置资料为 `D:\user\Documents\Career\AI\AI-Agents-in-Depth-zh-CN.pdf`。由项目作者本人维护资料来源，负责内容审核和更新。该路径记录当前选定来源，不代表资料已完成入库或覆盖全部目标技能；资料使用授权仍待确认。

### 4.2 用户补充资料

用户可以选择提交课程、笔记或其他参考资料，并明确是否将其用于当前计划。产品在内置知识的基础上结合这些内容调整任务与参考资源。

首批仅支持与 AI Agent 开发工程师方向相关的 Markdown 和 TXT 文件。该格式限制适用于用户补充资料，不限制产品维护者导入已选定的内置 PDF 资料。

- 不上传资料也能生成计划。
- 上传资料后应展示处理状态；失败时允许重试或继续使用内置知识库。
- 计划应区分内置来源和用户资料来源。
- 用户资料不得自动进入公共内置知识库，也不得供其他用户检索。
- 资料存在冲突或依据不足时，应说明问题，不默认为用户资料一定正确。

## 5. 功能需求

### 5.1 基于技能缺口生成计划

计划以匹配报告为依据，围绕尚未覆盖和部分覆盖的技能生成。用户应能理解每项任务对应哪个岗位要求、解决什么缺口。

生成时使用内置知识库，不要求用户提供资料。可选资料和可选截止日期用于调整计划；缺少这些信息时不阻塞生成。

首版不收集每周可投入时间等学习时间信息，作为后续迭代方向。

对已覆盖技能，避免机械地重复安排入门任务；存在明确前置知识需要时，应解释安排原因。没有技能缺口时，明确提示，不为凑计划而制造缺失项。

### 5.2 学习计划输出

计划按合理顺序组织为阶段，每个任务至少包含：

- 学习目标及对应技能缺口。
- 需要掌握的具体知识点。
- 可执行的学习或实践步骤。
- 明确的产出与完成标准。
- 参考资料及使用建议。

“学习 Python”或“完成一个项目”不能单独作为合格任务。任务应具体到用户能够开始执行，并判断自己是否完成。

若提供截止日期，应说明任务安排与时间约束；明显无法容纳必要学习内容时，应提示调整范围或期限，不能通过压缩日期伪装成可执行计划。由于首版不收集每周可投入时间，日期安排仅作为建议，不保证用户能在期限内完成。

### 5.3 来源与依据

用户可以从任务查看参考资料名称、来源链接或相关片段，理解推荐内容的依据。

来源应真实存在并与任务相关。不得把模型生成的说明伪装成资料原文，也不得编造链接、课程或引用。引用定位的具体交互留待设计阶段确定。

### 5.4 知识覆盖不足

内置知识库不足以支持某项技能时，应明确展示缺少支持的部分和对计划完整性的影响。

已有依据的部分仍可生成；对缺少依据的部分，不输出伪装为可靠结论的详细任务。补充资料可以作为可选补救方式，但产品不能把默认内容建设的责任转交给用户。

### 5.5 计划版本与进度

用户可以保存、重新打开计划并更新任务进度。刷新后，任务内容、参考来源和进度应保持一致。

学习计划生成后，其核心内容和参考依据作为快照保存；当前版本允许更新任务进度。用户主动调整或重新生成时创建新版本，不覆盖旧版内容。

```text
当前计划 V1
  → 用户触发调整或重新生成
  → 成功生成计划 V2
  → V2 成为当前版本，V1 成为只读历史版本
```

- 历史版本保留原内容和当时进度，用户可以查看，不直接编辑。
- 新版本生成失败时，原计划仍为当前版本，原进度不受影响。
- 新任务的学习目标与完成标准仍一致时，可继承旧任务的完成进度；不能仅因标题相同就自动继承。
- 无法确认仍然有效的进度不自动继承，但保留在旧版本中，不能因重新生成而丢失历史记录。
- 知识库更新或上传新资料不自动生成新版本，也不静默修改已有计划。

具体任务对应与进度继承判定规则留待技术方案细化。

### 5.6 学习辅助问答

用户可围绕任务或知识点提问，获得基于可用知识资料的解释和参考依据。资料不足时应明确反馈。

问答用于帮助理解和执行任务，不是使用学习计划的必经步骤。第一阶段可先通过任务中的资料入口完成学习支持，独立问答页面在后续补齐。

## 6. 迭代范围与优先级

### 第一阶段：内置知识库支撑计划

- 围绕 AI Agent 开发工程师方向确定技能目录，审核并导入首批内置资料。
- 在不上传用户资料的情况下生成具体学习计划。
- 展示任务对应的技能缺口、参考依据和完成标准。
- 支持知识不足提示、生成失败反馈与重试。
- 保存计划快照与任务进度，完成真实业务流程及离线知识覆盖验收。

### 后续阶段：补充资料与学习问答

- 用户选择补充资料参与计划生成。
- 用户资料管理、处理状态与来源区分。
- 从学习任务进入资料检索或问答。
- 按已确认的版本原则提供计划调整、重新生成、历史查看和有效进度继承。
- 根据需要增加每周可投入时间等可选信息。

### 本次不包含

- 自动联网搜索、抓取并无限扩充知识库。
- 覆盖其他职业和全部技能的通用学习平台。
- 复杂多 Agent 编排和自动完成学习任务。
- 通过简历推断用户真实熟练度或承诺录用结果。
- 强制用户上传学习资料后才能生成计划。
- 面向用户的评测仪表盘；知识覆盖评测作为开发者离线验收工具。

## 7. 验收标准

### 7.1 用户流程验收

| 场景 | 预期结果 |
| --- | --- |
| 新用户仅提供岗位和简历 | 在内置知识覆盖范围内，可直接生成学习计划，无必填资料上传步骤 |
| 报告包含缺失或部分覆盖技能 | 计划能够对应到这些缺口，任务有具体行动和完成标准 |
| 用户查看任务依据 | 可以找到真实、相关的来源；内置资料与用户资料可区分 |
| 知识库仅覆盖部分缺口 | 明确标识覆盖不足，不编造资料或把计划包装成完整方案 |
| 未上传资料或资料处理失败 | 不阻塞基于内置知识库的流程，清楚说明补充资料未被使用 |
| 保存计划并更新进度 | 重新打开后内容和进度一致，已有计划不被后台静默覆盖 |
| 生成失败或报告没有缺口 | 展示明确状态；失败可重试，无缺口时不制造学习任务 |

验收需使用真实岗位样例、简历和内置资料，核对计划的相关性、可执行性及来源支持程度，不能只以接口成功或页面显示为通过标准。

补充资料与计划版本功能在对应阶段验收：

- 用户补充资料仅接受 Agent 开发工程师方向的 Markdown、TXT，其他格式或范围有明确反馈。
- 调整或重新生成成功后，新版成为当前版本，旧版内容与当时进度保留且只读。
- 生成新版失败时，当前计划与进度不变。
- 仅对目标和完成标准仍一致的任务继承完成进度；同名但要求变化的任务不得自动标记完成。

### 7.2 离线知识覆盖评测

评测面向开发者，通过测试数据和脚本运行，不需要为其新增用户页面、业务接口或业务数据库表。评测规模、指标组合和通过阈值待讨论，不预设 85% 或 90% 为通用合格线。

```text
目标岗位技能与典型问题
  → 人工标注相关资料和预期依据
  → 运行检索并检查结果
  → 区分失败原因
  → 补充缺失内容或改进检索与生成
```

评测包含以下维度：

- 主题覆盖：目标技能是否有相关资料，哪些技能仍为空白。
- 问题覆盖：典型学习问题能否找到正确依据。
- 计划支持：资料能否支撑前置知识、学习顺序、实践任务和完成标准。
- 检索效果：区分资料不存在与资料存在但未检索到；检索正确但生成错误需另行分析。

指标含义必须区分：

- `Hit@K`：测试问题中，前 K 个结果至少命中一个相关片段的问题占比。
- `Recall@K`：对每个问题，前 K 个结果命中的相关片段数占全部标注相关片段数的比例；汇总时明确平均方式。
- 若每题恰好只有一个相关片段，上述命中率与平均召回率一致；有多个相关片段时不能直接等同。不能将“100 个问题中 88 个命中”直接作为一般意义的 `Recall@K`。

知识覆盖是否足够由目标范围和评测结果判断，不由 PDF 数量判断；问答检索表现不能单独证明学习计划可执行。

## 8. 待明确事项

以下事项不影响核心产品方向，但应在具体实施前确定：

- AI Agent 开发工程师方向的具体技能目录及当前资料的覆盖缺口。
- 内置资料的使用授权。
- 离线评测的数据规模、标注规则、指标组合与通过标准。
- 新旧任务对应关系及有效完成进度的具体继承规则。

本 PRD 描述目标需求，不代表所列能力已经实现；模型调用方式、数据结构、索引方案和接口设计另行形成技术方案。
