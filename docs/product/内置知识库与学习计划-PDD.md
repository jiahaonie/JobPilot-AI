# 内置知识库与学习计划 MVP 产品设计

日期：2026-09-09

状态：基于已确认 Demo 的产品设计，待实现与验收。

## 1. 设计结论与范围

本轮将匹配报告中的优先技能缺口转为有资料依据的学习任务。用户无须上传资料，即可生成计划、查看任务与参考原文，并更新学习进度。

采用已确认的交互：侧边栏“学习计划”可展开、收起，“当前计划”作为其子项。现在只展示当前计划，后续版本管理迭代再加入按时间标注的历史版本。

- 需求依据：[内置知识库与学习计划 PRD](./内置知识库与学习计划-PRD.md)。
- 视觉与交互参考：[学习计划 Demo](./学习计划-Demo.html)。
- 复用匹配报告、学习计划列表、计划详情和任务状态功能。
- 本轮补充具体任务、参考依据、覆盖范围和必要的异常反馈。
- 不新增资料管理后台、上传页面、学习问答、计划重生成或版本切换。

本文定义页面、交互与业务规则。数据库、接口字段、导入流程、检索策略和生成提示词在技术方案中说明。

## 2. 核心流程

```text
打开匹配报告
  → 查看优先技能缺口
  → 点击“生成学习计划”
  → 检索内置资料并生成任务
  → 完整保存本次有效结果
  → 自动打开计划详情，侧边栏选中“当前计划”
  → 阅读任务、展开依据、执行行动
  → 更新任务状态与进度
```

已有计划时，报告页直接提供“查看学习计划”，不再次生成。部分技能有资料时，生成这部分任务并列明未覆盖技能；全部资料不足时不创建计划。

首批内置资料为 `AI-Agents-in-Depth-zh-CN.pdf`，由项目作者维护和审核。资料已经获准用于本轮预期用途，但本文不代表已完成入库或验证其全部技能覆盖范围。

## 3. 页面与导航

### 3.1 侧边栏学习计划菜单

```text
匹配报告
▾ 学习计划
    当前计划
    匹配报告 #24
```

“匹配报告 #24”为当前计划子项的辅助说明，用于标识所属报告。编号由真实数据决定。

- 点击“学习计划”切换展开或收起，箭头同步变化。
- 展开时，如果当前报告已有计划，打开该计划；收起只隐藏子菜单，不切换右侧内容。
- 点击“当前计划”打开详情；详情打开时自动展开菜单，并高亮该子项。
- 切换到匹配报告页后，取消当前计划的选中高亮；菜单可以保持展开。
- 当前报告尚无计划时，菜单显示“暂无计划，请先从报告生成”，不展示可点击的空计划。
- 生成成功后，菜单出现“当前计划”并选中。

本轮不显示历史日期、版本编号、灰色占位版本或“即将上线”入口。菜单结构预留扩展位置，不代表已实现版本管理。

### 3.2 多份报告的归属

“当前计划”指当前选中报告对应的计划，不代表所有岗位共享一份计划。

从匹配报告或计划列表打开计划时，更新其报告上下文。切换到另一份报告时，导航应同步该报告的计划状态，不沿用上一份报告的计划。

沿用已有学习计划列表作为跨报告选择入口。没有明确报告上下文时，点击“学习计划”先打开列表；选择后再显示对应的“当前计划”。Demo 只演示一份报告，列表用于实际产品中多份报告的选择，不属于版本切换。

### 3.3 页面布局

沿用 Demo 的浅色背景、绿色主操作、卡片和留白。学习计划详情采用“主内容 + 辅助信息”的布局：

```text
侧边栏           主内容                         辅助信息
学习计划         标题、来源报告、返回入口        目标岗位
  当前计划       任务完成进度                    关联报告
                 技能覆盖说明                    学习顺序
                 按技能分组的任务卡片            截止时间
                   学习内容                     使用步骤
                   具体行动
                   完成标准
                   可展开的参考依据
```

窄屏下将导航与辅助信息顺序排列，任务卡片保持单列，避免横向滚动。菜单和引用展开使用可通过键盘操作的控件，选中、展开及加载状态应明确可辨。

## 4. 匹配报告页：生成入口

保留现有匹配报告内容，在优先技能缺口之后提供学习计划生成区域。

- 标题：“把技能差距，变成下一步行动”。
- 说明：“结合内置资料，将优先技能缺口转成具体任务。每项任务包含行动建议、完成标准和参考原文，无须上传学习资料。”
- 主按钮：“生成学习计划”；已有计划时改为“查看学习计划”。
- 辅助说明：“生成成功后自动保存；一份匹配报告对应一份计划。”

沿用报告中的优先技能顺序，不增加优先级调整或新的用户信息收集步骤。现有可选截止日期可继续沿用，不新增个性化排期表单；未设置时展示“未设置 · 自主安排”。

生成期间禁用生成按钮，显示“正在生成学习计划…”。不显示虚构百分比，也不把尚未保存的内容展示为正式计划。保存成功后自动进入详情。

## 5. 学习计划页：任务与依据

### 5.1 计划列表

沿用现有列表，每张计划卡片展示关联报告、任务状态、已完成任务数、进度和“继续学习”入口。有岗位信息时展示岗位名称，帮助区分不同报告。

部分覆盖的计划增加简短说明，例如“部分覆盖：Docker 暂缺资料”。该说明不替代详情中的完整未覆盖技能列表。

没有计划时显示空状态，提供“查看匹配报告”入口。列表加载失败时提供重试，不显示成“没有计划”。

### 5.2 详情顶部

- 主标题：“技能补齐计划”。
- 来源：目标岗位、关联匹配报告；提供“查看匹配报告”入口。
- 任务进度：百分比与“已完成 X / Y 项任务”。
- 覆盖说明：本次已覆盖的优先技能，以及未覆盖技能。

全部覆盖时，简要说明已覆盖当前报告的全部优先技能；部分覆盖时，用提示卡片列出未覆盖技能及资料不足的原因。

示例文案：“当前资料覆盖 2 / 3 项优先技能。Docker 暂未找到足够的参考资料，未生成对应任务。”示例技能和比例不构成真实资料覆盖承诺。

任务完成进度与技能覆盖范围分开表达。完成全部任务后显示“本计划任务已完成”，不能表述为“已掌握全部岗位技能”。

### 5.3 任务卡片

按技能分组，沿用报告的优先技能顺序；组内任务按执行顺序排列。每项任务包含以下信息：

| 区域 | 展示内容 |
| --- | --- |
| 任务标识 | 顺序编号、对应技能、适用的阶段标签 |
| 标题与学习内容 | 明确本项任务要理解或练习的具体内容 |
| 具体行动 | 用户可实际执行的阅读、整理或实践动作 |
| 完成标准 | 可自查的结果或产物要求 |
| 参考依据 | 资料名称和可展开的相关原文片段 |
| 任务状态 | 待开始、进行中、已完成 |

不强制每个技能固定生成三项任务。阶段标签帮助理解任务，不作为模板填充要求。禁止仅生成“学习某技能”“完成最小实践”等缺乏具体内容的任务。

实践动作可以根据原文知识设计，但不能将模型设计的练习要求伪装成原文内容。参考片段应实际支持任务涉及的知识点。

### 5.4 参考依据

资料名称常显，原文默认收起，点击“参考依据”展开或收起。一个任务有多条依据时，逐条展示来源与片段。

- 正式功能展示真实资料名称及原文，不能仅提供资源搜索词。
- 页码、章节只有在确实保留并可核对时才展示，不生成虚构定位。
- 本轮不要求 PDF 在线预览、跳转阅读器或从任务进入问答。
- 依据与任务内容一同保存，刷新后仍展示生成当时的依据。

### 5.5 更新任务状态

复用现有任务状态规则。用户可以从“待开始”进入“进行中”或“已完成”；从“进行中”回到“待开始”或标记“已完成”；已完成任务需要重新学习时回到“进行中”。

更新期间禁用对应控件。保存成功后更新任务样式及汇总进度；保存失败时提示“状态更新失败，请重试”，保留上一次成功保存的状态和进度。

完成任务后使用绿色状态提示，保留任务内容和依据供回顾。刷新或重新打开页面后，任务内容、引用和进度仍然保留。

## 6. 状态与失败反馈

| 状态 | 页面反馈与操作 | 保存规则 |
| --- | --- | --- |
| 没有优先技能缺口 | “当前报告没有需要优先补齐的技能，无须生成计划。” | 不创建计划 |
| 正在生成 | “正在生成学习计划…”，禁用重复生成 | 未成功前不呈现正式结果 |
| 全部目标技能有依据 | 自动打开详情，显示覆盖说明 | 保存计划、任务及依据 |
| 部分技能缺少资料 | 打开详情，明确列出未覆盖技能 | 保存有效任务、依据和未覆盖说明 |
| 所有目标技能均缺少资料 | “当前内置资料不足以支持这些技能，暂未生成计划。” | 不创建空计划 |
| 生成或保存失败 | “生成失败，计划尚未保存。请重试。”，提供重试入口 | 不保存残缺的失败结果 |
| 已有计划或重复请求 | 打开已有计划 | 不重复创建、不覆盖内容和进度 |

检索服务异常属于系统失败，不能伪装成“资料不足”。生成失败也不能降级为通用模板并提示成功。

如果请求超时，无法确认是否已经保存，应先核对该报告是否已有计划，再决定打开结果或允许重试；此时使用“暂未确认生成结果，请重试查看”等反馈，不能直接断言未保存。

详情读取失败时显示“计划加载失败，请重试”；已有内容不可用时，不展示假的空计划。资料不足说明应提示当前能力边界，不把反复重试作为主要解决办法。

## 7. 兼容与后续扩展

### 7.1 既有计划

一份匹配报告仍只对应一份计划。早期规则生成的既有计划继续可查看、更新进度，保留原有内容，不自动补造任务依据或重新生成。

既有计划没有参考原文时，展示说明：“此计划由早期规则生成，未附参考原文。”不把缺少引用渲染成加载失败。

早期规则计划是既有数据，不等同于同一计划的历史版本。它仍通过所属报告的“当前计划”进入；正式产品不提供“查看旧版计划”场景选择器。

### 7.2 版本管理扩展位置

后续版本管理迭代可以在“当前计划”下方加入按生成时间标注的历史版本，属于同一报告的版本才放在同一列表中。

历史版本只读、重生成、当前版本切换与进度继承遵循后续需求设计。本轮仅完成菜单结构，不提供这些功能，也不将其列入本轮验收。

### 7.3 Demo 与正式功能的区别

Demo 顶部场景选择器仅用于评审，不进入正式产品。模拟岗位、分数、技能覆盖、任务和引用均用于示意，不能作为真实效果证据。

Demo 进度在刷新后重置；正式功能必须持久化。Demo 使用固定的单报告样例；正式功能按真实报告归属展示。Demo 没有验证资料入库、检索和生成质量。

## 8. 验收场景

采用少量真实岗位、简历和选定资料，完成浏览器流程与人工原文核对。以下是待执行标准，不代表已经验收通过。

1. **导航与归属**：学习计划菜单可展开、收起；点击当前计划打开对应详情并高亮。无计划时显示空提示；切换报告不串用其他报告的计划。
2. **首次生成**：无须上传学习资料，从有技能缺口且尚无计划的报告生成计划，成功后自动进入详情，并出现当前计划子项。
3. **任务与依据**：任务包含具体内容、动作和完成标准；展开后可见真实来源与原文，人工核对确认能够支持任务知识内容。
4. **覆盖边界**：无缺口时无需生成；部分资料不足时明确列出未覆盖技能；全部资料不足时不创建空计划，不编造引用。
5. **失败与重试**：生成或保存失败有反馈且无残缺结果；重试成功后可打开计划。重复请求不创建第二份计划，不覆盖既有进度。
6. **状态与兼容**：任务状态保存成功后进度正确；失败时保留上次状态。刷新、重新打开后内容和进度保留；早期规则计划保持原样且无伪造依据。

实施时运行与改动匹配的检查与测试，并记录真实浏览器验收结果。不以完整技能目录、固定命中率门槛或评测页面作为本轮前置条件。
