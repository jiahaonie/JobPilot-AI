# 第一版：求职分析与学习计划 MVP

日期：2026-09-09

状态：第一版开发完成，已通过本地自动化检查；真实模型、真实资料质量和浏览器完整流程仍需按部署环境验收。

## 迭代结论

第一版把最初的项目规划落成了一个可运行的单用户 Web MVP，打通了以下核心流程：

```text
录入岗位 JD
  → 调用 LLM 分析岗位要求
  → 保存或上传简历并提取技能
  → 绑定岗位与简历
  → 生成带证据的匹配报告
  → 根据技能缺口检索内置资料
  → 生成带引用的学习计划
  → 更新学习任务进度
```

除网页主流程外，项目还通过 REST API 提供知识库检索、带引用问答和 Agent 工具调用能力。

## 为什么进行这次迭代

项目最初只有产品目标和后端模块规划，尚不能支持用户完成一次真实的求职准备流程。本次迭代的目标是先验证最关键的产品闭环：系统能否把一份岗位 JD 和一份简历转化为可解释的技能差距，再利用受控学习资料生成可执行、可追溯的学习任务。

因此，第一版优先解决三个问题：

1. 将岗位、简历、分析结果和学习进度持久化，避免核心结果只存在于单次模型响应中。
2. 为岗位分析、技能匹配和学习计划保留原文证据或引用快照，降低不可解释输出的风险。
3. 提供可操作的前端流程，让用户能够完成创建、分析、匹配、查看报告和执行计划，而不只依赖 Swagger 调试接口。

## 修改了什么

### 后端结构与数据生命周期

- 建立 `api → services → repositories → models/schemas` 分层，LLM、RAG 和 Agent 作为可替换、可测试的集成边界。
- 使用 SQLAlchemy 保存业务数据，并通过 Alembic 管理数据库结构及后续迁移。
- 将“保存原始内容”和“调用 LLM 分析”拆成两个显式动作。模型调用失败时，岗位或简历原文仍然保留，可重新分析。
- 岗位名称或 JD 发生变化时使当前岗位分析失效，但保留既有匹配报告快照，避免历史结论被新数据静默改写。
- 匹配逻辑升级为可解释的 V2 契约，保存岗位要求、简历技能、已匹配技能、缺失技能和优先补齐技能快照。

### 前端使用流程

- 用 React、TypeScript 和 Vite 替换初始化演示页面，增加仪表盘、岗位、简历、匹配报告和学习计划页面。
- 支持岗位创建、查看、编辑、删除和状态更新；编辑岗位名称或 JD 前提示分析失效影响。
- 支持简历文本保存及 TXT、Markdown、电子 PDF 上传，并允许用户单独触发或重试技能分析。
- 在岗位详情中串联简历绑定、岗位分析和匹配报告生成。
- 在匹配报告中展示匹配分、技能证据和学习计划入口；在侧边栏按当前报告展示对应计划。
- 在学习计划详情中区分技能覆盖率与任务完成进度，展示具体内容、行动、完成标准和引用依据。

### 可靠性与边界处理

- 为 LLM 结构化输出增加 Pydantic 校验、有限修复与明确错误处理。
- 为知识检索保留 Top-K、余弦距离过滤和引用 ID 校验；无可靠证据时，问答流程拒绝生成无依据答案。
- 为学习计划区分资料不足、知识库不可用、生成失败、超时和保存失败，不用通用模板掩盖真实异常。
- 对相同匹配报告只保存一份正式计划，并在重复请求或结果状态不确定时优先查询已有结果。
- 日志和配置不写入 API Key，不默认记录完整简历或资料正文。

## 增加了什么

### 核心业务能力

- 岗位 CRUD、投递状态和结构化 JD 分析。
- 简历文本保存、电子文件上传和技能提取。
- 岗位与简历绑定、技能匹配及历史报告查询。
- 普通知识文档入库、Chroma 向量检索和离线 Retrieval Evaluation。
- 带引用问答，以及检索证据不足时的拒答机制。
- 基于已审核内置资料的 `rag_v1` 学习计划：保存技能覆盖结果、具体任务和引用原文快照。
- 对既有 `rule_v1` 规则计划的读取兼容。
- 一个单步 Agent 工作流，可在参数校验后调用以下真实业务工具：
  - `get_job_requirements`
  - `compare_resume_with_job`
  - `search_learning_material`
  - `create_study_plan`

### 工程能力

- 单元测试、API 集成测试、数据库迁移测试和检索评测用例。
- 内置电子 PDF 导入脚本，以及真实检索与学习计划生成 smoke 脚本。
- DeepSeek、FastEmbed、Chroma、SQLite 和 Alembic 的配置与本地运行说明。
- 对模型、向量索引和数据库的依赖注入边界，便于使用替身覆盖异常场景。

## 第一版范围

第一版采用单用户、本地或单实例运行方式，重点验证求职分析和学习计划闭环。当前不包含：

- 用户注册、登录与多用户权限隔离。
- 自动抓取招聘网站、自动投递或自动联系招聘者。
- 扫描件 PDF、加密 PDF 和 OCR；简历与内置资料仅支持可提取文字的电子 PDF。
- 用户侧知识库管理页面；内置学习资料由作者通过命令行导入并配置。
- 学习问答页面、计划重生成、计划版本切换和个性化排期。
- 复杂多 Agent 编排、MCP 服务、后台任务队列和高并发部署能力。
- 将匹配分解释为录用概率；该分数仅代表项目内部技能覆盖规则。
